# Prerequisites — Focus Lock (Android)

Everything needed **before and during** development: toolchain, environment, Android permissions, device-owner provisioning, libraries, assets, scaffolding checklist, and testing setup. Read this before writing code.

---

## 1. Hardware

- **Development machine:** 8 GB RAM minimum (16 GB recommended), ~20 GB free disk (Android SDK + emulator images).
- **Android device (strongly recommended for testing):** a physical phone running Android 8+ (API 26+). Blocking, overlay, lock task, and device-owner behavior cannot be validated reliably on an emulator alone.
- **Dedicated/secondary device for owner-mode testing:** device-owner provisioning typically requires a device with **no Google/other accounts** and is usually done after a factory reset. Use a spare phone, never your daily driver.
- **USB cable** and working `adb`.

> Note: the current dev container is Ubuntu Linux (aarch64) with Node 24 and Python 3 but **no Android SDK/JDK detected**. Android Studio/SDK/JDK must be installed (see §3) or development done on a machine that has them. This must be reported before coding begins.

## 4. Android permissions and special access

These must be declared in the manifest and requested/explained in-app. Status is shown in onboarding with deep links to settings.

| Permission / access | Manifest entry | How user grants | Needed for |
|---|---|---|---|
| Accessibility | `<service>` with `BIND_ACCESSIBILITY_SERVICE` + accessibility config XML | Settings → Accessibility → Focus Lock → enable | Foreground-app detection, Reels/Shorts detection, dismiss actions |
| Overlay | `SYSTEM_ALERT_WINDOW` | Settings → Apps → Special app access → Display over other apps | Block overlay in personal mode |
| Notifications (API 33+) | `POST_NOTIFICATIONS` | Runtime permission dialog | Ongoing session notification |
| Usage access | `PACKAGE_USAGE_STATS` | Settings → Security/Privacy → Usage access | Secondary foreground-app detection |
| Ignore battery optimizations | `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` | System dialog / Settings | Keep service alive across OEM battery managers |
| Exact alarms (API 31+) | `SCHEDULE_EXACT_ALARM` (or `USE_EXACT_ALARM` where applicable) | Settings → Apps → Special app access → Alarms & reminders | Deadline completion under doze |
| Boot completed | `RECEIVE_BOOT_COMPLETED` | Granted on install (manifest) | Restore sessions after reboot |
| Foreground service | `FOREGROUND_SERVICE` + type (`mediaPlayback` / `specialUse`) | Manifest + notification | Timer and music services |
| Internet | `INTERNET` | Manifest | Streaming audio + (optional) VPN domain rules |
| Read external docs | URI permission via `ACTION_OPEN_DOCUMENT` | File picker | Local music files |
| Device owner | `DeviceAdminReceiver` + `<device-admin>` meta-data XML + `BIND_DEVICE_ADMIN` | adb/QR provisioning | Disable apps, lock task, true hard lock |

Important implementation notes:
- Accessibility permission must be granted manually by the user; there is no runtime API to grant it.
- On API 34+, foreground service types are enforced — declare the correct `android:foregroundServiceType`.
- On some OEMs (Xiaomi, Samsung, OnePlus, etc.) additional "auto-start" / "allow background" settings are required; document per-OEM guidance.
- Never request more than needed in personal mode; privileged calls must be guarded by mode detection.

## 5. Device-owner provisioning (owner / kiosk mode)

Owner mode is **optional** and is the only way to achieve true hard lock (disable apps, pin the UI, prevent uninstall). Follow carefully.

### 5.1 Requirements
- A device with **no accounts** signed in (factory reset a spare device).
- The focus app **installed before** provisioning.
- `adb` available on the host, USB debugging enabled on device.
- A `DeviceAdminReceiver` declared in the manifest, exported, with `android:permission="android.permission.BIND_DEVICE_ADMIN"` and `<meta-data android:name="android.app.device_admin" android:resource="@xml/device_admin" />`.
- `device_admin.xml` declaring the needed policies (e.g. `uses-policies` for `disable-applications`, lock-task related flags where applicable).

### 5.2 Provision via adb
```bash
# install the signed APK first
adb install -r focus-lock.apk

# set the app as device owner (replace with your applicationId + receiver path)
adb shell dpm set-device-owner com.example.focuslock/.admin.DeviceAdminReceiver

# verify
adb shell dumpsys device_policy | grep -i owner
```

If the command fails with "Device Owner is already set" or account errors: factory reset, skip account setup, enable USB debugging, and retry before adding accounts.

### 5.3 Provision via QR code (alternative)
Generate an enrollment QR containing the device-owner extras for the app, scan it from a fresh device during setup. Useful for multiple devices; host tooling is outside this project's scope but documented as an option.

### 5.4 Programmatic setup in app (after provisioning)
```kotlin
val dpm = context.getSystemService(Context.DEVICE_POLICY_SERVICE) as DevicePolicyManager
val admin = ComponentName(context, DeviceAdminReceiver::class.java)
// allow lock task for own package
dpm.setLockTaskPackages(admin, arrayOf(context.packageName))
// at session start, from the focus Activity:
startLockTask()
// at session end:
stopLockTask()
```

### 5.5 De-provisioning (must be shipped/documented)
```bash
# from the device owner app itself:
DevicePolicyManager.clearDeviceOwnerApp(context.packageName)

# or via adb (force):
adb shell dpm remove-active-admin com.example.focuslock/.admin.DeviceAdminReceiver
# factory reset is the universal fallback
```
De-provisioning must restore all disabled apps and lock-task settings first. Test this path.

### 5.6 Safety rules
- Maintain a denylist of critical system packages that must never be disabled (launcher, SystemUI, Settings, Phone, the app itself).
- Store each app's original enabled state and restore exactly.
- Never leave the device in lock task if the service crashes — use watchdog/alarm restoration.

## 9. Testing setup

### 9.1 Emulator (basic UI)
```bash
# create/start via Android Studio AVD Manager, or:
avdmanager create avd -n focus_api35 -k "system-images;android-35;google_apis;arm64-v8a"
emulator -avd focus_api35
```

### 9.2 Physical device (required for real validation)
```bash
adb devices                       # device shows as "device"
adb install -r app-debug.apk
adb shell dumpsys activity top    # inspect foreground activity during tests
adb logcat | grep FocusLock       # debug logs
```

### 9.3 Manual test scenarios (from spec §11)
1. Create named 1-minute session → verify name appears in notification/overlay.
2. Countdown accuracy and single `finishSession()` (check logs).
3. Owner mode: blocklisted app disabled at start, restored at end.
4. Personal mode: open blocked app → HOME + overlay within ~1s.
5. Open Reels/Shorts → dismissal + BlockEvent recorded.
6. Attempt to exit session (no control; PIN abort when configured).
7. Deadline: audio fades/stops, lock/overlay released, apps restored, summary shown.
8. Reboot mid-session → state restored.
9. All three music sources; local URI persists after restart.
10. Screensaver covers screen, stays awake, pinned in owner mode.
11. Revoke each permission → explanatory UI, no crash.
12. History/stats correctness.

## 10. Distribution / policy notes

- Device-admin/device-owner and Accessibility APIs are restricted by Google Play policy; this app is primarily intended for **sideload, enterprise, or personal use**. Note this in `README.md`.
- Sign releases with your own keystore (Android Studio → Generate Signed Bundle/APK). Keep the keystore out of version control.
- If sideloading, enable "Install unknown apps" for the source and document it.
- Provide the provisioning and de-provisioning instructions with any release.
